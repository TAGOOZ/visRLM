## Main Email Template

```
Hi Alex,

I hope this email finds you well. I'm reaching out because I built something I think you might find interesting — an interactive visualizer for your Recursive Language Models paper.

**Why I Built This:**

I created this for the OpenCode × Fireworks AI collaboration showcase, but more importantly, I wanted to make your groundbreaking research more accessible to developers who might find the paper intimidating.

Academic papers are goldmines of innovation, but the 20+ pages of dense research can be a barrier to entry. I wanted to make RLMs *playable* — something developers can explore interactively before diving into the full paper.

**What the Visualizer Includes:**

🌳 Interactive recursion trees — Users can click through query decomposition, see how the root LM delegates to sub-queries, and understand depth distribution. Built with React Flow for smooth interactions.

⚙️ REPL simulator — A step-through interface showing the Read-Eval-Print-Loop execution. Users can play/pause, adjust speed, and watch how the model writes code to inspect and manipulate context stored as Python variables.

💻 Code playground — Monaco Editor integration with your paper's code examples pre-loaded. Users can edit the peeking, grepping, and partition+map strategies and see how they work.

📊 Context visualizer — A heatmap showing token distribution and chunking strategies. Helps users visualize how 10M+ tokens get processed without clogging the context window.

**Design Approach:**

I went with a terminal aesthetic — deep black backgrounds, terminal green accents, monospace fonts (JetBrains Mono), information-dense layouts. The goal was "zero AI fingerprint" — no generic gradients, glassmorphism, or startup tropes. It looks like MIT researchers built it.

I studied your official visualizer (github.com/alexzhang13/rlm/tree/main/visualizer) and took inspiration from tools like Linear, Obsidian, and Stripe's documentation. The design serves the content, not the other way around.

**Tech Stack:**

- Next.js 14 with TypeScript (static export for easy deployment)
- Tailwind CSS + shadcn/ui (heavily customized for terminal theme)
- Framer Motion for purposeful animations
- React Flow for tree diagrams
- Monaco Editor for code editing
- Zustand for state management

**Links:**

- Live demo: [YOUR_URL]
- GitHub repository: github.com/[YOUR_USERNAME]/rlms-visualizer
- Built for: OpenCode × Fireworks AI collaboration showcase

The project is open source (MIT license) — I hope it can help more developers understand and appreciate your work.

**Feedback Welcome:**

I'd love to hear your thoughts! If you have any feedback, suggestions for improvement, or if I misrepresented any concepts, please let me know. I want this to be accurate and useful.

Also, if you find it valuable, I'd be honored if you shared it with your network. But no pressure at all — I built this primarily as a learning exercise and contribution to the community.

**Thank You:**

Your RLMs research is genuinely paradigm-shifting. The idea that smaller models (GPT-5-mini) can outperform frontier models through better architecture is a game-changer. I think 2026 will indeed be the year of RLMs, just as you predicted.

Thank you for advancing the field and making your work open and accessible. It's an inspiration.
```

## Email Tips

### DO:
- Keep it concise but informative
- Show you actually read the paper (reference specific details)
- Be humble — you're reaching out to an MIT researcher
- Make it easy for him to respond (clear questions)
- Include all relevant links upfront
- Mention the showcase context (shows legitimacy)
- Proofread carefully

### DON'T:
- Ask him to promote it (let him decide)
- Be overly familiar or casual
- Make it sound like you're asking for a job
- Send a generic template (customize!)
- Follow up more than once
- Get discouraged if no response (busy researchers!)

### Timing:
- Send Tuesday-Thursday
- Avoid Monday mornings and Friday afternoons
- Best time: 9:00-11:00 AM EST
- Wait 1 week before following up
